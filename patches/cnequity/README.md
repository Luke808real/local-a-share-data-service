# CNEquity local additive patch: valuation_metrics.turnover_rate

This directory records an **ASL-owned local patch** to the pinned CNEquity
runtime. It is not an upstream release and must never be presented as one.

```text
CNEQUITY_UPSTREAM_BASE   = 0.8.0 @ d453853da766b3ba3e44489c0fb6e0089243fa25
PATCH                    = 0001-valuation-metrics-turnover-rate.patch
PATCH_SCOPE              = additive column only
UPSTREAM_PR              = not submitted
```

## Why the patch exists

Daily Facts needs a canonical `turnover_rate`. The previous approach derived it
locally as `R3 volume / share_structure.float_shares * 100`, and the 2026-09-09
full-market shadow showed that denominator is a different basis from the
exchange's for part of the market (275 of 5198 keys, one-directional).

EastMoney's clist response already carries the exchange's own turnover rate in
field `f8`, on the same paginated bulk request CNEquity already makes for
`valuation_metrics`. Adding it costs no extra provider call and removes the
locally constructed denominator entirely.

## How it is applied

The CNEquity runtime is a git dependency resolved into `.venv`, not a checkout,
so the patch is applied to the installed package and its provenance recorded
here:

```text
cd /Users/luke808/ASL
patch -p1 -d .venv/lib/python3.12/site-packages < patches/cnequity/0001-valuation-metrics-turnover-rate.patch
```

`tests/test_valuation_turnover_rate_v01.py` asserts the patch is present in the
installed runtime, so a re-install that silently drops it fails the suite
rather than degrading behaviour.

## Backward compatibility

```text
schema change      additive: one new nullable Float64 column
primary key        unchanged (symbol, trade_date)
existing columns   unchanged in name, type and semantics
pe/pb/ps/float_mv  unchanged
compatibility      'additive' in the dataset registry, as before
```

One operational consequence, measured rather than assumed: CNEquity's
`validate_dataframe` requires every schema column to be present, so a partition
written before this patch cannot be validated after it. Any pre-patch
`valuation_metrics` partition must be rebuilt, not merely re-read. In this lake
that was two partitions, both replaced within the authorized bounded rebuild.

## Contract vintage

`contracts_registry_after_patch.json` is the registry contract generated by
`cne contract show --out` after the patch, and it validates
(`cne contract validate ... --against-registry` -> Contract OK). Its diff
against the shipped `contracts/v0.8.0.json` is exactly:

```text
added columns  : turnover_rate
removed columns: (none)
unit delta     : turnover_rate: PERCENT
```

The shipped `contracts/v0.8.0.json` inside the package was deliberately **not**
rewritten: it documents the upstream 0.8.0 release, and editing it would forge
an upstream artifact.
